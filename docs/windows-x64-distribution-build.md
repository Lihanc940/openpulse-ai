# Windows x64 CLI local distribution baseline

This is a maintainer procedure for task 14. It builds a local package for review. Do not upload the ZIP or create a public Release until both project owners choose and commit a root-level OpenPulse license.

## Prerequisites

- Windows x64, PowerShell 7, CMake 3.20 or newer, Visual Studio 2022 C++ tools and Windows SDK.
- JDK 21 or newer and the repository Maven wrapper for packaged-report Java Reader verification. The CLI itself does not need Java.
- Network access to the locked `nlohmann/json v3.11.3` Git tag, or an explicitly supplied clean local checkout of that exact tag. The script checks the local checkout's HEAD against the tag commit and refuses modifications. It never silently substitutes a cache.

From the repository root:

```powershell
.\scripts\build-windows-x64-package.ps1
.\scripts\verify-windows-x64-package.ps1 -PackagePath .\openpulse-analyzer\out\windows-x64\openpulse-analyzer-0.2.0-windows-x64.zip -JavaHome 'C:\path\to\jdk-21'
```

When GitHub is unavailable, an already verified local source checkout can be supplied explicitly:

```powershell
.\scripts\build-windows-x64-package.ps1 -NlohmannSource 'C:\path\to\nlohmann-json-v3.11.3'
```

The build script configures Release x64, builds, runs the complete CTest suite, installs only the runtime component, checks the install tree, writes the ZIP with sorted entries and fixed entry timestamps, and creates an adjacent `.zip.sha256`. Build and install scratch directories are unique and cleaned. The ZIP lives under the ignored `openpulse-analyzer/out/windows-x64/` directory. An old ZIP and hash for the same version are invalidated before compilation; failed builds remove incomplete outputs.

The verification script checks the exact archive layout, SHA-256 and timestamps, extracts to a fresh directory, runs packaged CLI v1/v2/error and space-containing path cases, checks summary safety and repeated output, inspects DLL dependencies with `dumpbin`, and passes reports generated by the packaged exe to the Java Schema and Reader contract tests. It fails if any mandatory tool or check is missing.

The generated ZIP has stable file names, ordering and entry timestamps. The Release executable uses MSVC `/Brepro`; two clean builds with the same source and toolchain produced identical ZIP hashes during task 14 verification. This does not establish byte-for-byte reproducibility across different MSVC, SDK, CMake or dependency toolchains. Record the source commit, tool versions, package size and SHA-256 for each reviewed build. SHA-256 detects file changes but is not a digital signature.

The MSVC runtime is linked statically. Verify the actual executable's imported DLLs on every release candidate; the current Windows x64 build imports only `KERNEL32.dll`. Do not infer dependency behavior from the CMake flag alone.
