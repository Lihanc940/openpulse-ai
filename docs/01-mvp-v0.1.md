# MVP v0.1 范围

第一版目标不是功能多，而是闭环稳定。

## 核心目标

用户输入一个 GitHub 公共仓库地址后，系统能够：

1. 解析 owner 和 repository。
2. 获取 GitHub 仓库基础信息。
3. 下载或克隆仓库代码到临时目录。
4. 调用 C++ 分析引擎扫描代码。
5. 读取 C++ 输出的 JSON 报告。
6. 计算项目健康评分。
7. 生成 AI 项目总结和优化建议。
8. 在前端展示分析结果。

## 必须完成

- GitHub 公共仓库地址输入
- 仓库基础信息获取
- 仓库代码下载或克隆
- C++ 文件遍历和排除目录
- 代码文件数量、总行数、注释行、空行统计
- README、LICENSE、CI、测试目录检测
- 基础复杂度规则
- 风险列表
- 健康评分
- AI 总结和建议
- 前端报告页
- Docker Compose 部署

## 暂时不做

- GitHub OAuth
- 私有仓库
- Gitee / GitLab
- 自动修改代码
- 自动提交 Pull Request
- 企业权限系统
- 多租户
- 大规模分布式扫描
- 完整安全漏洞检测
- 多语言 AST 全面支持

## 模块边界

### Java 后端

Java 负责业务流程和系统集成：

- 接收前端请求
- 管理用户、仓库、任务、报告
- 调用 GitHub API
- 下载仓库
- 启动 C++ 分析器
- 解析 JSON 结果
- 计算健康评分
- 调用 AI
- 提供前端 API

### C++ 分析引擎

C++ 负责本地代码扫描和静态分析：

- 遍历文件
- 识别文件类型
- 排除无关目录
- 统计代码规模
- 检查项目结构
- 检测基础风险规则
- 输出标准 JSON

C++ 不负责用户、数据库、前端页面和 AI 调用。

### Vue 前端

前端负责把结果展示清楚：

- 仓库输入页
- 项目列表页
- 项目概览页
- 代码分析页
- 风险列表
- AI 报告页

## 第一版完成标准

拿一个公开仓库作为示例，能完成：

```text
输入地址 -> 后端创建任务 -> 下载仓库 -> C++ 生成 report.json -> 后端保存结果 -> 页面看到评分和风险
```

如果这个流程稳定，v0.1 就成功了。
