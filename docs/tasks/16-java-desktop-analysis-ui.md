# OpenPulse AI 第十六步：Windows 桌面分析界面

## 任务定位

- 负责人：Java 负责人；C++ 负责人提供已验收的分析器和真实联调支持。
- 建议分支：`codex/desktop-local-analysis-ui`。
- 前置：任务 15 的多模块识别补丁通过验收；开工时核对其实际合并状态。
- 目标平台：Windows x64，中文优先。
- 技术选择：Java 21 + JavaFX 21 系列，Maven 固定依赖版本；开工时核对兼容的维护版本。
- 交付目标：双击软件，选择本地项目，点击分析，在窗口内读懂结果并保存 JSON。

2026-11-02 的真实试用证明 CLI 能生成报告，但用户需要学习 PowerShell、参数、编码和 JSON。用户明确将降低操作门槛的桌面界面列为下一步。CLI 继续服务自动化，桌面界面复用同一个 C++ 核心。

## 为什么单独做

实施进度（2026-11-02）：第一阶段“共享客户端”已通过 PR #35 合并到 `main`（`d86a81d`），记录见 [第一阶段验收](16-stage-1-analyzer-client.md)。第二阶段“桌面闭环”已本地实现，分支为 `codex/desktop-workflow-stage2`，尚未合并，结果见 [第二阶段验收](16-stage-2-desktop-workflow.md)。第三阶段便携分发尚未实施，整个任务尚未完成。

任务 15 修正扫描事实，本任务负责让人方便使用这些事实。发现规则和判定依据仍由分析器产生。桌面客户端应能离线启动，并把程序、分析器和运行环境一起交给用户。

JavaFX 适合当前 Java 分工，并提供原生目录和文件选择器。使用 JDK 的 `jpackage --type app-image` 交付含运行环境的应用目录，用户无需安装 Java；首先提供 ZIP 便携包，安装器另行安排。这个客户端与现有 Spring Boot 团队服务并列，启动时不依赖 Web 服务或数据库。

## 名词解释

- **桌面客户端**：用户双击后打开的本地窗口程序。
- **JavaFX**：用 Java 编写窗口、表格、按钮和文件选择器的工具库。
- **应用服务**：协调“开始分析、取消、读取报告”的代码，不负责画按钮。
- **后台任务**：在界面线程之外执行扫描，避免窗口卡死。
- **共享分析客户端**：供桌面端和团队服务共同调用的报告读取、校验和进程执行代码。
- **app-image**：带启动 exe、依赖和 Java 运行环境的完整应用目录。
- **不确定进度**：分析器未报告百分比时显示“正在分析”，不编造百分比。

## 用户操作闭环

```text
双击 OpenPulse.exe
  -> 选择项目文件夹
  -> 点击“开始分析”
  -> 窗口保持响应，可取消
  -> 显示概览、发现项、证据和建议
  -> 按需保存 JSON / 打开已保存报告
```

文件夹选择使用系统对话框，也允许粘贴完整路径。用户无需输入命令和报告参数。显式使用协议 `2.0`，分析器从应用目录定位，不能依赖系统 PATH。

## 建议代码边界

```text
openpulse-desktop/          JavaFX 窗口、展示模型、桌面应用服务
openpulse-analyzer-client/  最小共享报告与进程客户端（由现有 Java 实现抽出）
openpulse-platform/         Spring Boot 团队服务及其配置适配
openpulse-analyzer/         唯一的扫描事实和规则实现
```

```text
JavaFX 界面 -> 桌面应用服务 -> 共享进程客户端 -> C++ exe
                                               -> v2 JSON
JavaFX 展示模型 <- 已校验报告 <- 共享 Reader <-----+
```

先核对现有依赖图，再抽出 Reader、模型、Schema/语义校验和必要进程逻辑。可以保留原包名以缩小迁移。Spring 注解和配置绑定留在 Platform 适配层；共享客户端不依赖 Web、JPA 或数据库。不得复制一份 Reader 或另写宽松解析器。

抽取前记录原有行为和测试，抽取后原测试必须继续验证相同行为。仅新增用于构建这些模块的最小 Maven 聚合配置，并保留 Platform 的独立验证入口或明确记录等价的新命令。不要顺带重构 GitHub 下载、持久化或其他业务。

## 首屏与交互

首屏就是工作区：顶部为项目路径选择和分析/取消操作，下方为概览、发现列表和详情。界面使用简洁工具布局，中文内容完整可读。

必须实现：

1. 目录选择、路径校验及明确的开始入口。
2. 正在分析、成功、部分成功、失败和取消状态；进行中禁止重复启动。
3. 概览显示项目、分析器版本、状态、文件统计、语言统计和结构事实。
4. 发现列表显示严重程度、规则、问题；选择后显示原始证据与修复建议。
5. 部分成功时持续展示限制；失败报告不能显示成“没有问题”。
6. 保存 JSON、打开合法 v2 报告、重新分析。
7. 路径、规则与证据按普通文本展示；内容不能触发命令、脚本或自动打开任意外部链接。
8. 关闭窗口时处理在运行的分析进程与临时文件；报告保存失败有明确提示。

`COMPLETE`、没有发现项、检测到测试这三种情况，都不能展示成代码无缺陷或测试已通过。只呈现分析器提供的事实。

## 模型与配置

- UI 状态可采用 `EMPTY / READY / RUNNING / SUCCESS / PARTIAL_SUCCESS / FAILED / CANCELLED`，由单一应用服务协调。
- 界面模型与协议 DTO 分开；协议版本、规则 ID、严重等级和证据不得被 UI 改写。
- 以已有 `AnalyzerReportDocument` / `AnalyzerReportV2` 为协议事实来源。
- 默认超时沿用 30 秒，取消需终止进程树并清理临时目录；显示实际的超时结果。
- 用参数列表启动 exe，不拼接 Shell 命令。
- 设置报告大小上限并沿用严格 Reader；保留现有安全错误类别。
- 初版不持久化绝对项目路径和分析历史；报告只在用户选择保存时导出。

## 明确不做

- 不同时开发 Vue 网站、云端部署、登录、团队共享或数据库历史。
- 不接 AI API、Skill、MCP、自动更新、托盘常驻、异步队列或健康评分。
- 不复制 C++ 规则，不改变协议字段、CLI 默认版本或绕过 Reader 校验。
- 不在本任务扩展新的检测规则或实现通用多平台安装器。
- 不把 UI 完成当作产品价值实验、节省 Token 或扫描准确率已验证。

## 完成标准

1. 新用户解压后双击启动，选择目录并完成真实分析。
2. 报告内容与同版本 CLI 显式 v2 输出一致（仅允许 taskId/generatedAt 不同）。
3. 桌面与 Platform 共用严格 Reader 和必要进程逻辑，原有边界测试通过。
4. 分析中可操作窗口并取消，失败可恢复，不把上一次结果当作本次成功。
5. 可以导出并重新打开合法报告，错误消息能指导用户处理。
6. 最小便携包验收通过，中文说明与已知限制准确。
7. 工作区无生成产物、密钥或个人路径配置被提交。
8. PR 通过后再合并，公开发布单独执行；未发布时写清候选状态。
